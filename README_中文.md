# 水环境容量与风险评估集成平台（WEC-Risk Platform）· 使用说明书（中文）

> 版本 v1.0 ｜ 中英双语 ｜ 默认污染物：总氮 TN（可扩展 TP/COD）

把原本分散在 QGIS、SWAT、ERA5_Workbench 与数十个脚本中的全流程集成为**一个桌面程序**：
SWAT 仿真编排 → 关键因子筛选 → 动态自适应标准（CRS-ACM）→ 基础/实际水环境容量 →
两类风险指数 → 高风险区/传输热点 → 交互式地图可视化。支持任意 SWAT2012 工程**自动探测载入**（多流域迁移）。

---

**方式 A：直接用 .exe（推荐给最终用户）**
- 双击 `dist/WEC_Platform/WEC_Platform.exe`。整个 `WEC_Platform` 文件夹可整体拷贝分发。

**方式 B：源码运行（开发/调试）**
```bash
pip install -r requirements.txt
python main.py                      # 图形界面
python main.py --cli --project examples/miyun_project.json --year 2022 --reconcile   # 无界面对账
```

**界面语言**：菜单栏「语言 / Language」可在 中文 ⇄ English 实时切换。

## 二、前置条件：SWAT 建模需要做到哪一步？

本程序**不做流域划分/HRU/天气写入**（这些仍在 QSWAT/ArcSWAT 中完成），它从你**已建好并运行过**的 SWAT2012 工程读取结果。你需要在 QSWAT 里完成到以下程度：

| 步骤 | 是否需要手动 | 说明 |
|---|---|---|
| 1. 流域划分（Delineation） | ✅ 在 QSWAT 中完成 | 由 DEM 生成子流域与河网，得到 `Watershed/Shapes/subs1.shp`、`riv1.shp` |
| 2. HRU 定义 | ✅ **需自己在 QSWAT 中划分** | 叠加 CLCD 土地利用、HWSD 土壤、坡度分级，定义 HRU。本程序不替你划 HRU |
| 3. 天气数据 | ✅ 在 QSWAT 中导入并写入 | 降水/气温等导入 QSWAT 的 Weather Writer，生成 `.pcp/.tmp` 等并写入 SWAT 输入。**本程序无需再次导入天气**——天气已体现在 SWAT 输出里 |
| 4. 参数化与运行 | ✅ 在 QSWAT 中 Run SWAT | 必须勾选**月度输出**（IPRINT=月），运行得到 `Scenarios/<情景>/TxtInOut/output.rch`、`output.sub` |
| 5. （可选）率定 | 视需要 | 若做过率定，把率定后的情景目录作为本程序的工程情景 |

**本程序需要的最小文件集合**（自动探测）：
```
<工程根目录>/
├── Watershed/Shapes/subs1.shp(.dbf/.prj/.shx)   # 子流域多边形(+坡度Slo1/高程Elev/经纬度)
├── Watershed/Shapes/riv1.shp(.dbf/...)          # 河网(+河道几何 Len2/Wid2/Dep2)
└── Scenarios/<情景名>/TxtInOut/
    ├── file.cio          # 模拟期(IYR/NBYR/NYSKIP) -> 自动推断输出年份
    ├── fig.fig           # 河网拓扑(上下游关系)
    ├── output.rch        # 河段月度输出(流量、各形态氮通量)
    ├── output.sub        # 子流域月度输出(面源产污)
    └── SWAT*.exe         # (可选)有则可在程序内「运行 SWAT」
```

> **天气数据**：只在 QSWAT 建模阶段需要导入；建模运行后，气象的影响已经在 `output.rch/.sub` 中。**本程序不需要你再导入天气数据**。

## 三、数据放在哪里？自动识别还是手动录入？

| 数据 | 放置位置 | 识别方式 | 格式 |
|---|---|---|---|
| DEM / CLCD / HWSD | 任意（在「① 工程与数据」页登记路径） | **仅登记与校验**，不参与计算（建模已在 QSWAT 完成） | .tif / .mdb |
| SWAT 工程 | 选工程根目录 | **程序自动探测**子流域数、拓扑、面积、投影、输出年份、河道几何 | QSWAT 目录结构 |
| **点源污染** | 工程根目录 **或** 情景目录 | **按文件名自动识别**；也可在「④」表格手动录入 | 见下 |
| 标准表（可选） | 工程根目录 或 情景目录 | 自动识别 | 见下 |
| 监测数据（标定/验证用） | 任意 | 在「③ 标定与验证」页手动选择 | 见下 |

**点源文件命名与格式**（关键）：
- 文件名：`PL_Point_<污染物代码>_<年份>.csv`，例如 `PL_Point_TN_2022.csv`。
- 列：`Subbasin`（子流域编号）、`PL_point_TN_g_s`（点源通量，单位 **g/s**）。
  - ⚠️ **单位务必是 g/s**。若你的原始数据是年负荷，请换算：`g/s = 千克每年 ÷ (365 × 86400) × 1e3`（若是「克每年」则 `÷ (365 × 86400)`）。**切勿把 kg/yr 误当作 t/yr**（会导致数值偏大 1000 倍）。
- 程序按文件名中的年份自动归类。**只有存在该年专属点源文件的年份**，才会计算并显示「实际环境容量」与「风险」（见第六节）。
- 也可在「④ 交互地图与点源」左侧表格直接手填（g/s）后点「应用并重算」。

**标准表 `subbasin_water_quality_standards.csv`**（可选；缺省则全流域退回 GB Ⅲ类限值）：
- 至少包含：子流域编号列（如 `子流域ID(SUB)`）、标准限值列（如 `TN标准限值(mg/L)`）。
- 注：本程序**只用其中的限值数值**作为 `C_strict`；**不再显示功能区名称**（仅用编号表示，详见第八节）。

## 四、模拟年份、预热设置与多年平均基准

- 「② 运行仿真与分析」页顶部「模拟期与预热设置」会显示 `file.cio` 解析出的：**SWAT 模拟期**（如 2008–2025）、**内置预热 NYSKIP**（如 2008–2014，SWAT 已跳过、不在输出中）、**可分析的输出年份**（如 2015–2025）。
- **预热只能取早期连续年份**：通过「分析起始年份」下拉选择——其**之前**的输出年份将作为额外预热被自动排除，**之后**的年份用于"多年平均基准量"（基础容量 Wi、长期平均浓度、面源产污）。例如选 2017，则 2015–2016 视为额外预热，分析用 2017–2025。这样保证预热是早期连续段，不会误选中间年份。
- 下方实时显示「→ 用于多年平均的年份」。
- 注：2008–2014 是 SWAT 自身的预热（NYSKIP），不在 output 中、无法在本程序恢复；若要改这段，需在 QSWAT 改 NYSKIP 并重跑 SWAT。本程序允许把预热**向后延伸**到输出年份内。

## 四·补、交互地图的年份与底图

- 「④ 交互地图与点源」的**年份下拉列出全部输出年份**（不止有点源的 3 年）。年份后标注 `✓含点源` 或 `·仅标准/容量`：
  - 含点源年份（2020/2021/2022）：完整显示动态标准、基础/实际容量、两类风险、传输热点。
  - 无点源年份：**只显示动态自适应标准与基础环境容量**；切到该年时若当前在容量/风险图层会自动切到「动态标准」。待你获取该年点源后，在左侧表格录入并「应用并重算」即可得到该年的实际容量与风险。
- **传输热点**：在所有图层上以**红色虚线边框**标出（右下角有图例说明），随专题图层一同展示。
- **中英双语 + 全球底图**：地图右上角图层控件可切换多套**全球**底图——OpenStreetMap（本地语言/中文标注）、CartoDB Voyager/Positron（英文/拉丁标注）、Esri 卫星影像（全球）。默认底图随界面语言自动选择（中文→OSM，英文→CartoDB Voyager），便于国内外推广。

## 五、标定逻辑（关键因子阈值如何确定、是否影响其他年份、如何流向新标准）

**关键因子筛选**（「③」页自动展示）：基于 SWAT 模拟数据做 MI + Spearman 相关分析，附 p 值与 bootstrap 入选率。这是"已标定模型上的驱动力分析"。

**阈值标定的三种模式**（决定动态标准里每个因子的阈值 T）：
1. **SWAT 分位数（provisional）**：用该因子在各子流域上的分位数（默认中位数）作阈值，无需外部数据，标注为暂定。
2. **监测数据 ROC/Youden**：需提供监测 CSV，用 Youden 指数求最优切点（最严谨）。
3. **手动**：在因子表里直接填阈值。

**标定所需监测数据格式**（用于「ROC 标定」与「有效性验证 AUC」）：
- CSV，列：`Month`（时间序）、`TN`（该污染物月度浓度）、`Algae`（生物响应，如藻细胞密度）。
- 验证逻辑：对 TN 做 1 个月时滞对齐，以 `Algae > 阈值` 为真值，计算动态体系 AUC 与静态对照（复刻原方法学的"切断自循环"思路：标准判定与生物验证因子相互独立）。

**应用范围（逐年 vs 全局）—— 回答"用 2022 标定是否会影响其他年份"**：
- 「应用范围」选 **所有年份**：写入全局标定，所有年份的动态标准随之更新。
- 「应用范围」选 **仅当前年份**：写入"逐年标定"，**只有当前年份**的动态标准/容量/风险改变，其他年份不受影响。
- 因此：若你切到 2022、用 2022 数据标定、并选"仅当前年份"，则**只有 2022 变化**，2020/2021 保持不变。✔

**新阈值如何流向新标准/容量/风险（自动、同步）**：
点「执行标定并刷新动态标准」后，程序会按该年生效的标定**自动重算**：
```
新阈值 → 动态自适应标准 C_dynamic → 基础容量 Wi(以 C_dynamic 为目标) → 实际容量 → 两类风险/热点
```
地图、详情、图表会立即同步刷新——**你不需要手动再算任何一步**。

## 六、点源与实际环境容量（只对有点源的年份相减）

- 实际水环境容量 `W_actual = 基础容量 Wi − 该年点源(kg/d)`，点源 `kg/d = g/s × 86.4`。
- **只有存在该年专属点源文件（或你在表格里手动录入）的年份**，才会计算并显示实际容量与两类风险。
- 缺少点源的年份（如本工程的 2015–2019、2023–2025）：**不输出实际容量与风险**，仅显示动态标准与基础容量；地图相应图层显示为灰色"无数据"，详情面板给出提示。
- 「④」页的"年份"下拉**只列出含点源的年份**（本工程为 2020/2021/2022）。
- 面源输送率也按**该年点源**一并计算，保证同一年内各量自洽。

## 七、两类风险定义（互不重叠）

- **第一类风险（本地）** `LP = 实际(校正后)非点源通量 / 实际水环境容量`（专利 式7）。
- **第二类风险（上游传输）** `TR = 上游流入污染物通量 Influx / 实际水环境容量`（专利 式8）。
  - `Influx_i = Σ 上游各子流域的 Outflux`；`Outflux_i = (Influx_i + 本地面源 + 本地点源) × (1 − R_i)`。
- 两者分子分别为"本地"与"上游来量"，**互不重叠**，可精准溯源："本地治理"还是"上游治理"。
- 等级：`<0 → Ⅴ级超载(赤字) · ≤1 → Ⅰ级 · ≤2 → Ⅱ级 · ≤3 → Ⅲ级 · 否则 Ⅳ级`。
- 传输热点：第二类风险 ≥ Ⅳ级 且 外来贡献比(Influx/Outflux) ≥ 0.5。

## 九、操作流程（五个页签）

1. **① 工程与数据**：选 SWAT 工程根目录 →「自动探测并新建工程」；登记 DEM/CLCD/HWSD/天气路径（仅记录）；查看摘要与校验。也可「载入密云示例工程」。
2. **② 运行仿真与分析**：勾选参与多年平均的模拟年份 →「运行 SWAT 仿真」（如有 exe，自动接阶段A）或直接「运行分析链路（阶段A）」。
3. **③ 标定与验证**：查看因子筛选；选模式与应用范围做阈值标定；导入监测数据出 AUC。
4. **④ 交互地图与点源**：编辑点源（g/s）→「应用并重算」；切专题图层/年份；**点击子流域**查看动态标准/容量/两类风险，叠加传输热点与拓扑流向。
5. **⑤ 概览图表**：实际容量分布、两类风险等级分布、动态 vs 原始标准、关键因子重要性。

## 十、核心公式（与已验证脚本严格一致）

- 动态标准：`C_dynamic = C_strict + (C_loose − C_strict)·调整指数`，`C_loose = min(C_strict+1.0, 2.0)`
- 因子隶属度（负相关）：`x≥T→0；x≤0.5T→1；中间线性`
- 基础容量：`Wi = a·[86.4·Q·(C_it − C_up) + 1e-3·K·V·C_it]`（a=0.8，K=0.05；**不截断负容量**；浓度质量加权并可设上限；水库子流域可设特例 K/V/C）
- 输送率：`R = (IN_river + 面源 + 点源 − OUT)/(IN_river + 面源 + 点源)`，按**该年点源**计算
- 实际容量：`W_actual = Wi − 该年点源`
- 风险：`LP = 校正面源/W_actual`；`TR = Influx/W_actual`

> CLI `--reconcile` 已对账：本程序输出的 `W_actual`、`LP` 与既有 `risk_index_TN_2022_corrected.csv` **逐列吻合（max|Δ|≈1e-12）**。

## 十一、迁移到新流域（多流域复用）

本程序"零路径硬编码、自动探测任意 SWAT2012 工程"，迁移到新流域**能跑通并出图**；但要得到**科学有效**的结果，需按下面"必做清单"换数据并重标定（这是方法学要求，并非工具局限）。

### 程序自动搞定的（无需你操心）
`自动探测并新建工程`后，自动读取：子流域数、河网拓扑(fig.fig)、面积、投影、输出年份(file.cio)、河道几何(riv1.dbf)、子流域属性(subs1.dbf)；整条管线与污染物(TN/TP/COD)均已参数化。

### ✅ 新流域必做清单
1. **在 QSWAT 建好并运行**该流域的 SWAT2012 工程（务必开启**月度输出** IPRINT=月），得到 `Watershed/Shapes/{subs1,riv1}.*` 与 `Scenarios/<情景>/TxtInOut/{file.cio,fig.fig,output.rch,output.sub}`（见第二节最小文件集）。
2. **"自动探测并新建工程"**：在「① 工程与数据」页选该流域工程根目录。
3. **放入该流域的标准表**（可选）`subbasin_water_quality_standards.csv`（含各子流域标准限值）；缺省则全流域退回 GB Ⅲ类，列名会自动猜测。
4. **放入点源文件** `PL_Point_<污染物代码>_<年份>.csv`（列 `Subbasin, PL_point_<code>_g_s`，单位 g/s）；无该年点源则该年只出动态标准与基础容量（不出实际容量/风险）。
5. **重新标定动态标准的因子阈值**（关键）：密云的阈值（坡度 19.153 / 高程 284.546）是**密云专属、不可照搬**。到「③ 标定与验证」用该流域监测数据走 ROC/Youden 标定（无监测则用 SWAT 分位数，标 provisional）。
6. **按需配置研究区相关修正**：若该流域有水库/极值浓度问题，手动设 `conc_clip_upper`（浓度上限截断）与 `reservoir_overrides`（水库子流域的 K/V/目标浓度）——见下方"边界说明"。
7. **"保存工程"** 生成 `.wecproj.json`，下次"打开工程"即可。

### ⚠️ 诚实说明的边界（密云专属参数不会泄漏到其它流域）
`detect()` 中有一段判断——**仅当**工程名含 "miyun" 或情景为 `Miyun_Calib_01` 时，才套用密云专属参数：浓度上限截断 7.0 mg/L、SUB32 水库特例(K=0.025/V=2e9/C=1.0)、以及"密云水库"命名（见 `wec_platform/project.py` 的 detect）。
- **其它流域不会触发该分支**，拿到的是**通用默认**：无浓度截断、无水库特例、因子阈值待标定——因此**绝不会把密云的参数泄漏到你的流域**。
- **代价**：新流域的水库特例与浓度截断**需你手动配置**（程序不自动识别水库本体）。若你的流域没有大型水库/极端浓度，保持默认即可。

## 十二、常见问题

- **Q：地图没有底图？** 底图(OpenStreetMap)与 Leaflet 库需联网；离线时子流域专题多边形仍正常渲染，仅缺底图。
- **Q：某些年份点不出风险？** 该年没有点源文件，按设计不输出实际容量/风险（第六节）。
- **Q：标定后数值没变？** 确认点了「执行标定并刷新动态标准」；若选了"仅当前年份"，只会改当前年份。
- **Q：英文界面仍有个别中文？** 数据本身的中文（如来自标准表的文本）不翻译；界面文字均已双语。
